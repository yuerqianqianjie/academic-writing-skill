# Contributing

Contributions should preserve the source-grounded and workflow-oriented nature of this skill.

## Before editing

- Read `SKILL.md` and the relevant reference file.
- Check `references/source-map.md` before reconciling apparently conflicting guidance.
- Keep source-derived guidance separate from workflow rules added to operate the skill.
- Do not add generic advice merely to make a reference longer.

## Content rules

- Preserve source attribution and source-specific scope.
- Do not turn one journal's rule into a universal convention.
- Do not remove an unresolved source difference; document how the skill should handle it.
- Do not add invented references, examples, evidence, methods, numerical results, or disciplinary requirements.
- Prefer rhetorical functions and diagnostic questions over fixed sentence templates.
- Preserve tentative claims and technical terminology.

## Structural rules

- Keep `SKILL.md` focused on routing and workflow.
- Put substantial, conditional guidance in `references/`.
- Add a reference only when it supports a distinct task or improves progressive disclosure.
- Update `README.md`, `CHANGELOG.md`, and `references/source-map.md` when the public behavior or source coverage changes.
- Add or update a case in `examples/validation.md` when a routing or safeguard changes.

## Validation checklist

- Skill frontmatter remains valid.
- All local Markdown links resolve.
- No scaffold placeholders remain.
- The revision does not change authorial meaning or certainty.
- The new behavior is represented by a validation case where practical.
- Any source conflict remains visible and scoped.
